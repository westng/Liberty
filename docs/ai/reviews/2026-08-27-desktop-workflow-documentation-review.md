| 主题 | 当前代码事实 | 文档口径 |

| 窗口作用域 | `job-workbench` 绑定来源、任务 ID 与临时 token，只能操作单个结果；它申请同任务子作用域并通知 `main` 创建 `ai-summary` 或 `meeting-notes` | 架构文档区分“申请子作用域”和“实际创建 WebView”，后者仍只属于 `main` |
| 窗口权限 | `job-workbench` 可读取结果、重命名说话人、导出及列出模板；`ai-summary` 可创建、恢复、选择和删除总结运行；`meeting-notes` 只读 | 不再把所有结果窗口统称为只读，按窗口角色列出最小权限 |
| 说话人真实性 | ASR 与 diarization 状态独立；只有 `completed` 且存在真实分段时进入已验证说话人投影，`unavailable` / `failed` 保留逐字稿且不生成默认标签 | README、更新日志与发布验收统一说明真实降级语义 |
| 设置与资源 | 设置页按分类导航，Python、ffmpeg 和模型资源分别展示来源、进度、状态及安装、修复或校验动作 | README 与架构文档不再只描述一个笼统的“环境与模型”安装入口 |
| ASR 调度 | 并发配置是上限；调度器预留 2 GiB、按 Runner 4 GiB 预算并发，并按实际并发分配逻辑 CPU；8 GiB 设备默认单任务 | README 提供用户可理解的约束，架构文档保留完整工程边界 |
| 质量门禁 | 根 `pnpm check` 包含契约、前端、Python、Rust、生产构建、Clippy 与 release checks；真实扫描、ASR 基准和跨平台验收仍是独立证据 | README 与发布文档不再把 `pnpm check` 缩写为少量前端/Rust 检查，也不把脚本自测冒充真实扫描 |
