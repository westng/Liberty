## 目标

将 Liberty 桌面客户端从偏网页后台的卡片式界面，重构为更接近 macOS 原生工具软件的界面体系。设计强调克制、清晰、可长期维护，同时保留现有业务能力和跨平台可用性。

本轮设计不修改系统设置页。`/settings` 保持现有页面结构、交互和视觉表现，只允许被新的应用壳层承载。

## 设计原则

1. **原生工具感优先**：使用 sidebar、toolbar、split view、table/list、inspector 等桌面软件常见结构。
2. **降低装饰密度**：减少大圆角、大面积半透明、强阴影、复杂渐变和过多卡片嵌套。
3. **提高信息效率**：任务、模型、模板、人员等管理页面以列表和详情面板为主，不再用大量大卡片表达基础数据。
4. **状态始终可见**：运行模式、模型状态、CPU、内存、图形估算、桌宠开关等保留在标题栏，但视觉保持紧凑。
5. **设置页隔离**：系统设置页不参与本轮视觉重构，避免影响已经稳定的运行时、主题和本地模型配置能力。
6. **跨平台一致，平台差异收敛**：macOS 优先贴近原生；Windows 保留自绘标题栏和窗口控制，但页面结构与 macOS 一致。

## 应用壳层

### 标题栏

- macOS 继续使用 overlay 标题栏，左侧避开红绿灯。
- 左侧保留性能指标：CPU、内存、图形估算。
- 右侧保留桌宠开关、模型/运行状态、GitHub。
- 控件高度保持紧凑，不使用外层大圆角容器。
- 可拖拽区域只放在标题栏空白区，不能覆盖菜单、按钮和主要内容。

### 侧边栏

当前侧边栏视觉偏品牌卡片，本轮改为 macOS 原生 sidebar：

- 宽度建议 `220px-240px`。
- 背景使用系统侧边栏质感：浅色低透明或纯色，深色使用低对比深灰。
- 导航项高度 `32px-36px`，圆角 `6px-8px`。
- 当前项使用浅色填充或 accent tint，避免强烈渐变。
- 品牌区收缩为小图标 + Liberty，不再占用大面积插画空间。
- 分组建议：
  - 工作：新建任务、任务列表、结果工作台入口由任务详情进入。
  - 资源：模型、模板、人员。
  - 伙伴：宠物中心。
  - 系统：系统设置。

### 主内容区

采用统一三层结构：

1. **Toolbar**：页面标题、面包屑/返回、主要动作、搜索/筛选。
2. **Content Split**：列表、表格、编辑器、详情区。
3. **Inspector**：右侧辅助面板，用于参数、状态、元信息和预览。

默认主内容边距建议 `12px-16px`，内部 gap 建议 `10px-14px`。

## 视觉系统

### 尺寸

- 主窗口最小推荐：`1180px × 760px`。
- 标题栏：`42px` 保持不变。
- 侧边栏：`220px-240px`。
- Inspector：`280px-340px`。
- 主列表行高：`36px-44px`。
- Toolbar 高度：`46px-56px`。

### 圆角

- 页面容器：`10px`。
- 面板和列表：`8px-10px`。
- 按钮、输入框、导航项：`6px-8px`。
- 不再使用大面积 `20px+` 圆角。

### 色彩

- 背景：接近 macOS system background。
- 侧边栏：接近 macOS sidebar background。
- 内容面板：纯色或极轻微 tint。
- 边框：使用 `1px` 低对比分隔线。
- Accent：沿用用户设置的 accent color，但只用于选中、主按钮和关键状态。
- 状态色必须配文字或图标，不只依赖颜色。

### 字体

- 首选系统字体栈：`-apple-system`, `BlinkMacSystemFont`, `SF Pro Text`, `Segoe UI`, `sans-serif`。
- 页面标题：`20px-22px / 600`。
- 区块标题：`14px-15px / 600`。
- 正文：`13px-14px / 400`。
- 元信息：`12px-13px / 400`。
- 表格数字使用 tabular figures。

### 动效

- 页面切换：轻微 crossfade 或无动效。
- 面板展开：`160ms-220ms`，只使用 opacity/transform。
- 按钮状态：即时反馈，避免夸张缩放。
- 遵守 `prefers-reduced-motion`。

## 页面设计

### 新建任务 `/`

定位：任务导入和参数确认控制台。

结构：

- Toolbar：标题“新建任务”、运行模式状态、开始按钮。
- 左侧主区：文件导入 drop zone、文件队列、音频基础信息。
- 中间/下方：任务名称、热词、摘要模板等关键参数。
- 右侧 Inspector：本地运行时状态、模型可用性、预计处理方式、最近任务入口。

交互：

- 文件拖入后立即显示文件队列，不把高级参数堆在首屏。
- 运行时未就绪时，主按钮禁用并给出明确原因和设置入口。
- 创建任务后进入任务详情或任务列表，桌宠触发“创建任务”文案。

### 任务列表 `/jobs`

定位：任务数据库。

结构：

- Toolbar：搜索、状态筛选、排序、新建任务按钮。
- 左侧可选窄筛选栏：全部、处理中、已完成、失败。
- 主区使用 table/list：任务名、状态、时长、创建时间、来源、操作。
- 右侧 Inspector：选中任务摘要、最近输出、快捷打开工作台。

交互：

- 单击选中，双击进入详情。
- 空状态给出“新建任务”主操作。
- 处理中任务使用进度/状态文本，不只显示颜色 badge。

### 任务详情 `/jobs/:id`

定位：单个任务的全生命周期详情。

结构：

- Toolbar：返回、任务名、状态、打开工作台、导出。
- 主区：转写时间线或内容列表。
- 右侧 Inspector：任务元信息、文件信息、处理参数、错误/日志摘要。

交互：

- 状态变化不跳动布局。
- 转写内容支持复制、定位、折叠长段落。
- AI 总结完成后显示进入工作台的明显入口。

### 结果工作台 `/jobs/:id/workbench`

定位：整理、校对、导出会议结果的编辑器。

结构：

- Toolbar：返回详情、导出、复制、重新总结。
- 左侧 segment/tabs：转写、纪要、AI 总结。
- 主编辑区：当前文档内容。
- 右侧 Inspector：导出格式、模板、任务上下文、快捷操作。

交互：

- 文档区尽量像原生文本编辑器，不使用厚重卡片。
- 导出操作集中在右侧 Inspector 或 Toolbar。
- AI 总结中要有明确处理中状态，并触发桌宠对应文案。

### 模型管理 `/models`

定位：本地模型资产库。

结构：

- Toolbar：模型状态、刷新、打开设置。
- 主区：模型列表，字段包括名称、用途、大小、状态、版本、操作。
- 右侧 Inspector：选中模型详情、下载进度、设备建议。

交互：

- 下载、安装、校验状态统一成进度行。
- 不可用原因必须直接显示。
- 避免把模型卡片做得过大。

### 模板管理 `/templates`

定位：摘要模板库。

结构：

- Toolbar：搜索、新建模板、导入/导出。
- 左侧列表：模板名称、默认标记、更新时间。
- 右侧预览/编辑入口：模板说明、适用场景、内容预览。

交互：

- 默认模板标记明显但克制。
- 编辑器页面保持简洁，避免复杂装饰。

### 人员管理 `/members`

定位：说话人和常用参会人词典。

结构：

- Toolbar：搜索、新增人员、导入/导出。
- 主区：联系人式列表或表格。
- 右侧 Inspector：姓名、别名、备注、关联任务统计。

交互：

- 支持快速搜索和键盘选择。
- 删除前确认，并提示影响范围。

### 宠物中心 `/pet`

定位：桌面伙伴管理面板。

结构：

- 顶部状态：宠物名称、阶段、心情、今日互动。
- 主区：宠物预览、互动按钮、事件记录。
- 右侧设置：桌宠开关、置顶、静音、专注模式、主动等级、多开。

视觉：

- 保留宠物趣味，但容器风格向系统偏好面板收敛。
- 不使用大面积半透明对话框。
- 事件记录使用紧凑 timeline/list。

## 系统设置页保持策略

`/settings` 不做页面内视觉重构：

- 不修改 `SettingsView.tsx` 的业务结构。
- 不重排设置项。
- 不替换设置页专属样式。
- 只允许外层 shell、标题栏、侧边栏变化自然影响它。
- 如果新的全局 token 影响设置页，需要显式回归检查。

## 组件体系

建议新增或重构以下通用组件：

- `AppSidebar`：应用侧边栏。
- `AppToolbar`：页面工具栏。
- `SplitPane`：主内容 + Inspector 布局。
- `InspectorPanel`：右侧详情/参数面板。
- `NativeList`：macOS 风格列表。
- `NativeTable`：紧凑表格。
- `SegmentedControl`：工作台内容切换。
- `StatusDot` / `StatusText`：状态表达。
- `EmptyState`：统一空状态。

组件命名要贴合现有 React feature 目录结构，避免过度抽象。每个组件职责单一，文件行数控制在可维护范围内。

## 实施阶段

### 阶段一：Shell 和 token

- 重构应用壳层、侧边栏、标题栏和内容容器。
- 建立 macOS native 风格 CSS token。
- 确认 Windows 自绘标题栏点击、拖拽和窗口按钮不回归。
- 设置页只做兼容检查，不做页面内改版。

### 阶段二：任务核心链路

- 改造新建任务、任务列表、任务详情、结果工作台。
- 优先保证创建任务、处理中、AI 总结中、完成、失败状态表达清晰。
- 保持桌宠文案触发链路。

### 阶段三：资源管理页

- 改造模型、模板、人员页面。
- 建立列表 + Inspector 的稳定模式。
- 优化空状态、加载态、错误态。

### 阶段四：宠物中心与统一打磨

- 改造宠物中心为原生偏好面板风格。
- 统一 hover、focus、disabled、loading 状态。
- 检查浅色、深色、macOS、Windows。

## 验收标准

1. `/settings` 页面保持原结构和主要视觉，不被重设计破坏。
2. macOS 下整体更接近原生工具软件，而不是网页后台。
3. Windows 下菜单、按钮、标题栏控制、桌宠拖拽不回归。
4. 所有主页面都遵循 toolbar + content + inspector 或等价结构。
5. 大卡片和大圆角显著减少，信息密度提高。
6. 状态、空数据、错误、加载都有明确表达。
7. 关键验证通过：`cargo fmt --all -- --check`、`cargo check --workspace --locked`、`pnpm desktop:typecheck`。
