# Liberty 项目级稳定性与安全重构设计

适用范围：Liberty 项目稳定性与安全重构方案
权威边界：本文保留历史设计背景，不代表当前实现；当前行为以代码、测试和正式文档为准

## 目标

本次改造不是逐条打补丁，而是统一修复以下根因：

- 本地与远端任务使用不同判定条件，导致读写落入不同数据源。
- 本地任务没有队列、互斥、进程登记和重启恢复。
- AI 总结依赖单次长请求，Word 导出再从自由文本二次猜测结构。
- Tauri 命令、文件路径、运行时下载和凭据缺少完整安全边界。
- SQLite 初始化、schema 迁移、跨窗口状态和发布门禁缺少统一生命周期。

## 核心原则

1. 数据源由显式配置决定，运行时是否就绪不能改变数据归属。
2. SQLite 是本地任务、总结版本、事件和奖励的唯一持久化事实源。
3. 长任务必须有持久化状态机、可恢复队列和单任务执行租约。
4. Word 只消费版本化的结构化会议纪要，不再把自由文本解析器作为主链路。
5. 所有外部输入先校验身份和边界，再执行文件、进程或网络操作。
6. 所有可见操作必须有一致的成功、失败、回滚和跨窗口通知语义。

## 1. 安全边界

### 任务标识和文件删除

- 本地任务 ID 只允许后端生成的规范格式，IPC 传入 ID 必须先验证。
- `job_dir` 返回的规范化路径必须确认仍位于 jobs 根目录内。
- 删除使用持久化 `job_deletion_ops`：先 fence 并取消当前 attempt，确认进程树退出，再写 tombstone、把目录同卷移动到回收区、提交逻辑删除并异步 GC。
- 启动时按删除操作状态恢复；物理删除前可以恢复内容，物理删除后必须可重试并最终收敛到 deleted。

### 原生命令

- 创建任务不再接受前端提供的 `runnerScriptPath`；脚本路径完全由后端资源解析。
- Windows 外部链接使用 ShellExecute 或 Tauri opener，不经过 `cmd /C`。
- 自定义 Tauri 命令按窗口角色拆分权限；只读窗口不能调用删除、设置、安装和凭据读取命令。
- 文件导出权限只覆盖用户通过保存对话框授权的目标；移除 `$RESOURCE/**` 写权限。

### 运行时供应链

- Python、FFmpeg 和离线模型资源使用不可变 URL，manifest 中 SHA-256 为必填字段；缺失即拒绝启动安装。
- 下载先写临时文件，校验通过后再原子发布；缓存复用前也重新校验。
- Python 依赖使用与 `runtimeVersion` 绑定的锁定清单；依赖清单变化必须提升 runtime 版本。
- 解压必须拒绝绝对路径、父目录跳转、逃逸符号链接和超额展开。

### 凭据

- 远端 token 与 AI key 均存系统凭据库，SQLite 只保存引用。
- 启动迁移把历史明文写入凭据库，成功后清空明文列；失败时不删除旧值并给出可恢复错误。
- 用户清空 key 时同步删除系统凭据；列表 API 不向无需 key 的窗口返回明文。

## 2. 任务数据源与执行引擎

### 显式数据源

- 新增 `processingMode: local | remote`，所有 list/get/create/retry/delete/rename/result/summary 操作都通过同一个 `MeetingJobService` 接口路由。
- 每条任务使用 `JobRef { source, backendProfileId?, id }` 作为稳定身份；缓存键和所有修改操作都使用复合引用。
- `processingMode` 只决定新建任务和默认列表，不能重新解释已打开任务或在途请求的数据归属。
- `backendUrl` 只是远端配置，不再隐式切换数据源。
- 远端模式缺少 URL、鉴权或协议能力时直接显示不可用，不回落本地。
- 远端握手返回协议版本、能力和上传限制。媒体上传采用 `beginUpload/uploadChunk/finalize/abort`，包含文件大小、SHA-256、幂等键、断点续传与超时清理；finalize 成功后才原子创建任务。
- 远端 API 补齐结果读取、删除、讲话人重命名和总结版本能力；不支持的能力在握手结果中禁用 UI。

### 本地调度器

- 引入进程级 `JobScheduler`，读取设置中的并发数，维护持久化 queued/running 状态和每任务互斥租约。
- 应用强制单实例；任务 claim 使用条件更新。每次执行分配单调 `lease_token` 和唯一 `attempt_id`，所有状态、结果和事件提交都必须匹配当前 token。
- 创建和重试只入队；调度器负责启动 runner，禁止同一任务并行执行。
- runner PID、进程启动身份、attempt、lease token、heartbeat、started_at 写入任务运行表；输出写入 attempt 独立目录，只有当前 token 能发布到任务结果。
- 应用启动时扫描 queued/running：没有持久控制通道时不按 PID 盲目接管，而是 fence 旧 attempt、终止可确认的旧进程树并重新排队或标记可重试失败。
- 应用退出时停止取新任务，并对子进程执行有界终止。

### 原子状态

- 结果分段、运行状态、耗时和事件在一个事务中提交。
- 进程日志写文件并增量发布摘要，不再每 400ms 把整份日志写回 SQLite。
- 前端轮询使用单飞调度和请求序号，旧响应不能覆盖新状态；远端和本地都遵循相同规则。

## 3. AI 总结与 Word 导出

### 长会议总结

- 请求前按估算 token 预算切分逐字稿，切分边界优先落在讲话人或时间段之间。
- AI summary run 也进入持久化调度：固定逐字稿 revision，逐块幂等保存，最终合并使用 fencing token 条件提交；重启后只重跑缺失块。
- 每个分块返回结构化 speaker reports；最终合并阶段按稳定 speaker key 合并、去重并验证人员覆盖。
- 解析 OpenAI 响应时必须检查 `finish_reason`；`length`、缺失字段或覆盖校验失败不能标记 completed。
- 完成的 summary run 同时持久化原始结果、版本化 `MeetingMinutesPayload`、源分块和完整性诊断。

### 人员覆盖不变量

- 开启讲话人时，逐字稿中的非空讲话人集合必须全部出现在 payload 的 participants 和 speaker reports 中。
- AI 未返回某人时生成明确的空报告并标记 `missing_from_ai`，不能静默丢弃。
- AI 返回的未知人员保留原文并标记 unmatched；人员管理只补充 member id、规范姓名、部门和排序。

### Word 渲染

- DOCX 只读取指定 summary run 的结构化 payload。
- 渲染会议信息、出席人员、每人上周总结/本周计划/个人总结、全局总结、议题、决策、行动项、风险和跟进事项。
- 输出先写同目录临时文件，完整生成并校验 ZIP 后再原子替换目标，失败不破坏已有文档。
- 输出使用唯一同目录临时文件、flush/fsync、重新打开验证 ZIP，并拒绝符号链接目标；不支持可靠原子替换的文件系统明确报错。
- 删除非活动 run 不改变活动版本；删除活动版本时事务内选择 `completed_at DESC, id DESC` 的最新完成版本，无候选则置空并向用户提示。

## 4. 前端与多窗口生命周期

- 主窗口独占全局轮询、系统通知、daily-open 和桌面宠物同步；standalone 窗口不运行这些副作用。
- 新增 Tauri 跨窗口事件总线，任务、总结、模型、模板、成员和状态通知保存后广播变更。
- 持久化修改使用事务 outbox/change sequence；事件携带实体 revision，窗口按 revision 去重，并在聚焦或发现序号缺口时重新同步。
- 主窗口收到事件后按实体 ID 精确刷新；不再通过 hydration 逻辑永久保留旧总结。
- 状态通知由主窗口统一呈现；独立窗口同时保留本地错误区，不能依赖主窗口状态栏显示失败。
- 设置使用字段 patch、`settings_revision` 和 `UPDATE ... WHERE revision = expected`；冲突返回最新快照。保存成功后才提交全局状态并广播 revision，失败恢复旧外观和旧表单。
- 编辑窗口维护 dirty 状态；切换记录或关闭窗口前确认，不能静默销毁草稿。

## 5. 数据库与发布

### 数据库

- 在读取或修改业务表前先校验 schema 版本。
- 初始化只创建最小 `app_meta` 后读取版本；未来版本数据库在任何业务 DDL 前拒绝。
- 使用有序、事务化 migration 列表逐版本升级，并在成功提交后推进版本号。
- 迁移持有跨实例排他锁，并在升级前通过 SQLite Backup API 生成一致备份；迁移到凭据库版本后禁止降级到不识别凭据引用的旧版本。
- 初始化在进程内只执行一次；连接启用 WAL、busy timeout 和合理 synchronous 策略。
- 新增任务运行、事件幂等和必要的凭据引用迁移；迁移必须支持旧数据库夹具测试。
- 每个连接启用 `foreign_keys=ON`、`busy_timeout` 和 `synchronous=NORMAL`，数据库启用 WAL；claim/CAS 使用短 `BEGIN IMMEDIATE` 事务，事务内禁止网络、进程等待和文档生成。

### 宠物、农场和小游戏

- 所有奖励使用持久化事件键唯一约束，不使用“最后一个事件键”判断幂等。
- AI 总结奖励键使用 summary run id；同一 run 重放不奖励，不同 run 分别奖励。
- 所有每日规则统一使用后端本地日期服务。
- 农场和小游戏的刷新使用单飞请求并在窗口隐藏时暂停；领奖与状态变化在同一事务完成。

### Git 与 CI

- 把被生产代码引用的新增源码和必要资源纳入版本控制；生成目录、虚拟环境、日志和大体积临时输出进入 `.gitignore`。
- PR 和主分支执行 TypeScript 类型检查、Rust fmt/test/Clippy、发布安全检查和关键集成测试。
- Release 构建依赖通过的门禁；禁止移动已有标签和覆盖已有版本。
- 所有资产上传并校验完成后再发布 Release；标签内版本元数据必须与二进制一致。

## 实施分波

1. 安全边界、数据库 migration runner 和基础事件/调度接口。
2. 本地任务调度器、显式数据源和远端能力契约。
3. 结构化 AI 总结、人员覆盖校验和原子 Word 导出。
4. 多窗口生命周期、设置事务和前端单飞刷新。
5. 宠物/游戏幂等、Git 资产治理和 CI/Release 门禁。

每一波都必须保持 TypeScript 类型检查和 Rust 测试可运行；跨模块接口先落类型和测试，再替换调用点。
