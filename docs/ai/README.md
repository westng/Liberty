# Liberty AI 过程文档

## 定位

本目录保存 Liberty 开发过程中需要评审、追踪或交接的设计、计划、调研、诊断和审计快照。这里的内容是过程证据，不自动代表当前实现，也不替代代码、测试、接口契约、根 README 或 `docs/` 下的正式文档。

是否放入本目录取决于文档职责，而不是是否使用过 AI 辅助编写。面向用户、开发者或运维长期维护的内容应放在稳定的正式文档路径。

## 分类

- `designs/`：架构、交互、数据模型或技术方案。
- `plans/`：已确认目标的分阶段实施计划与验收项。
- `research/`：调研、问题复现、诊断过程与证据整理。
- `reviews/`：代码、架构、安全、发布或数据审计快照。
- `handoffs/`：未完成事项、上下文、风险与下一步交接。

目录按需创建。原 Superpowers 插件已弃用，其历史设计和计划分别迁入本目录的 `designs/` 与 `plans/`。迁移只调整文档归属并补充治理元数据，不表示正文中的旧技术事实、完成度或适用版本已经重新确认。

旧 `docs/superpowers/` 路径不得恢复或继续引用。迁移文档统一标记为“历史快照”；使用其中结论前，必须重新核对当前实现和正式文档。

## 必填信息

每份过程文档开头至少声明：

```markdown
文档类型：设计 / 计划 / 调研 / 评审 / 交接
状态：草案 / 待确认 / 已确认 / 已完成 / 历史快照 / 已废弃
创建日期：YYYY-MM-DD
最后核实：YYYY-MM-DD
适用范围：涉及的模块、平台、版本或用户流程
权威边界：本文能证明什么，不能替代什么
依据：当前代码、测试、日志、文档或外部来源
```

无法核实的事实应标为“未核实”，并说明缺少的证据及其对结论的影响。路径、行号、运行状态、测试结果、外部版本和完成度都属于易失信息，引用前必须重新检查。

## 生命周期

- 设计或计划得到确认后，将长期约束同步到代码、测试、契约或正式文档。
- 实施完成后，核对验收项和当前行为，再将过程文档标记为已完成、保留为历史快照或删除。
- 过程文档不得成为接口、数据库规则、安全要求、运行时清单或发布流程的唯一依据。
- 不记录聊天全文、提示词、隐藏思考过程、临时日志、秘密、机器或地区专属配置，以及未经脱敏的用户媒体信息或生产数据。
