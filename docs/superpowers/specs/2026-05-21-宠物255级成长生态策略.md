# Liberty 宠物 255 级成长生态策略

## 背景

Liberty 的桌面宠物不是传统游戏宠物，而是工作陪伴型成长系统。它的核心价值不是让用户刷数值，而是让用户感觉：自己的真实工作被记录、被回应，并逐步沉淀成一个长期陪伴关系。

当前系统已经具备这些基础能力：

- 工作行为可以给宠物增加成长值。
- 工作行为可以产出 LP。
- LP 可以购买食物、道具、装扮、场景。
- 食物可以提供固定成长值。
- 宠物可以通过气泡台词、动作、成长值动画回应用户。

接下来需要把这些能力统一成完整生态，而不是分散的功能点。

## 设计目标

- 等级上限定为 `255` 级，形成长期成长目标。
- 前期升级要快，让用户每天能感受到反馈。
- 中后期升级逐步变慢，但不能让用户觉得停滞。
- 食物经验值固定，不随宠物等级衰减。
- 等级越高，升级所需成长值越多，因此食物贡献占比自然下降。
- LP 主要来自真实工作行为，食物是成长加速器，不是唯一主线。
- 宠物反馈围绕被照顾、陪伴、恢复精神和一起成长，而不是纯数值播报。

## 设计边界

这份策略定义的是宠物长期成长生态，不是一次性 UI 改版说明。

必须坚持的边界：

- 第一阶段仍是本地能力，不依赖账号、云同步或联网权益。
- LP 不是现实货币，不允许出现充值、提现、交易等现实金融表达；付费抽卡、付费概率掉落也不允许进入设计。
- `福利 / 每日盲盒` 属于本地免费日常福利，不消耗 LP、不关联充值、不出售次数，和付费抽卡系统严格区分。
- 宠物成长不能阻塞会议任务、转写、AI 总结、导出等核心流程。
- 任何奖励失败都应降级为 best-effort，不影响用户完成工作。
- 等级成长服务长期陪伴，不应制造焦虑、排名或竞争压力。
- 商品解锁以明确条件为主，不能使用模糊概率或隐藏保底。

落地前的历史实现使用过线性等级：

```text
level = floor(experience / 20) + 1
stageProgress = experience % 20
```

因此 255 级策略不能只把等级上限数字改成 255，必须把旧线性等级迁移为“累计经验驱动的等级曲线”。

## 核心循环

```text
真实工作行为
→ 获得成长值和 LP
→ 使用 LP 购买食物、道具、装扮、场景
→ 食物提供固定成长值
→ 宠物升级、突破阶段、解锁内容
→ 宠物用动作、台词、动画回应用户
→ 用户形成长期陪伴感
```

## 成长值来源

成长值分为两类：

| 类型 | 来源 | 定位 |
|---|---|---|
| 工作成长值 | 每日打开、创建任务、转写、总结、导出、互动 | 主线成长 |
| 食物成长值 | 用户使用 LP 购买并喂食 | 加速成长和情感反馈 |

工作成长值代表用户真实使用 Liberty。食物成长值代表用户把工作获得的 LP 转换成对宠物的照顾。

## 工作奖励建议

| 行为 | 成长值 | LP | 说明 |
|---|---:|---:|---|
| 每日打开 | +2 | +5 | 每日轻量奖励，按自然日去重 |
| 创建任务 | +5 | +8 | 鼓励启动工作流 |
| 开始转写 | +2 | +3 | 轻量过程奖励 |
| 完成转写 | +12 | +18 | 核心工作奖励 |
| 完成 AI 总结 | +10 | +15 | 核心工作奖励 |
| 导出结果 | +6 | +10 | 闭环奖励 |
| 点击/抚摸/鼓励 | +1 | +1 | 情感互动，每类每日限制 |

一个普通用户完成一次完整工作流时，大致获得：

```text
成长值：35-45
LP：45-60
```

这是后续等级曲线和食物价格的基础假设。

### 后期工作奖励系数

140 级以后如果仍然只按基础奖励发放，升级会明显变慢。后期变慢是合理的，但不能让用户感觉真实工作没有反馈。

因此建议引入“工作奖励阶段系数”：

```text
工作成长值 = 基础成长值 × 成长值阶段系数
LP = 基础 LP × LP 阶段系数
食物成长值 = 固定成长值，不参与阶段系数
```

核心原则：

- 长期使用 Liberty 的用户，真实工作带来的成长反馈应该变厚。
- 食物成长值必须保持固定，不能跟随等级膨胀。
- LP 可以随阶段小幅提升，但必须比成长值更保守，避免商店经济通胀。
- 阶段系数只作用于工作流奖励和每日打开，不作用于购买、装备、成就自动解锁。

推荐成长值系数：

| 等级段 | 成长值系数 | 说明 |
|---|---:|---|
| Lv.1-30 | 1.00x | 新手期按基础奖励 |
| Lv.31-60 | 1.15x | 稳定使用后略微提升 |
| Lv.61-100 | 1.30x | 进入习惯期 |
| Lv.101-140 | 1.45x | 中期开始抵消曲线上升 |
| Lv.141-180 | 1.60x | 深度陪伴期保持推进感 |
| Lv.181-220 | 1.75x | 长期用户获得更厚反馈 |
| Lv.221-255 | 2.00x | 终局阶段承认长期投入 |

推荐 LP 系数：

| 等级段 | LP 系数 | 说明 |
|---|---:|---|
| Lv.1-60 | 1.00x | 避免早期购买过快 |
| Lv.61-140 | 1.15x | 支撑中期装扮和场景 |
| Lv.141-220 | 1.30x | 后期给长期用户更多消费能力 |
| Lv.221-255 | 1.45x | 终局仍保持保守通胀 |

示例：

```text
基础完整工作流成长值：35-45
Lv.141-180 后：约 56-72
Lv.181-220 后：约 61-79
Lv.221-255 后：约 70-90
```

这样后期等级仍然更慢，但用户每天完成真实工作时不会只看到很小一截进度。

计算时建议四舍五入到整数，并在事件流水里记录基础值、系数和最终值，方便后续调参。

## 等级上限

宠物等级上限为 `255`。

`255` 级不是为了让用户短期刷满，而是提供长期陪伴目标。用户前期应该快速升级，中期稳定推进，后期把升级变成长期沉淀。

## 等级阶段

阶段用于表达陪伴关系，不直接等同于稀有度。

| 阶段 | 等级范围 | 名称 | 情感定位 |
|---|---:|---|---|
| 1 | Lv.1-10 | 小小初遇 | 它刚来到桌面，开始认识用户 |
| 2 | Lv.11-30 | 轻轻熟悉 | 它开始熟悉用户的工作节奏 |
| 3 | Lv.31-60 | 稳定陪伴 | 它能稳定回应用户的工作状态 |
| 4 | Lv.61-100 | 一起成长 | 用户和宠物形成习惯性陪伴 |
| 5 | Lv.101-140 | 默契养成 | 宠物反馈更温柔，更贴近用户节奏 |
| 6 | Lv.141-180 | 深深羁绊 | 宠物成为长期工作陪伴的一部分 |
| 7 | Lv.181-220 | 长久相伴 | 宠物承载长期使用记忆 |
| 8 | Lv.221-255 | 不离不弃 | 最高陪伴阶段，强调纪念和沉淀 |

## 升级曲线

升级曲线采用分段递增。前期升级频繁，后期升级成本逐步上升。

| 等级段 | 每级所需成长值 | 阶段体验 |
|---|---:|---|
| Lv.1-10 | 15-30 | 新手期，快速反馈 |
| Lv.11-30 | 35-60 | 熟悉期，基本每天可升级 |
| Lv.31-60 | 70-110 | 稳定期，1-2 天一级 |
| Lv.61-100 | 120-180 | 成长期，2-3 天一级 |
| Lv.101-140 | 200-280 | 默契期，3-5 天一级 |
| Lv.141-180 | 300-400 | 深度期，4-6 天一级 |
| Lv.181-220 | 430-560 | 长期陪伴，约 1 周一级 |
| Lv.221-255 | 600-800 | 终局沉淀，长期目标 |

建议采用公式生成，而不是为 255 级手写表。

推荐公式：

```text
required_exp(level) = round(base(level) * stage_multiplier(level))
```

也可以先用分段表实现，后续再抽象为公式。

### 推荐曲线公式

实际实现建议使用分段线性插值，避免指数曲线后期过陡。

`level` 表示当前等级，`required_exp(level)` 表示从当前等级升到下一级需要的成长值。`Lv.255` 为满级，不再计算下一级需求。

```text
required_exp(level):
  Lv.1-10    = lerp(15, 30, level, 1, 10)
  Lv.11-30   = lerp(35, 60, level, 11, 30)
  Lv.31-60   = lerp(70, 110, level, 31, 60)
  Lv.61-100  = lerp(120, 180, level, 61, 100)
  Lv.101-140 = lerp(200, 280, level, 101, 140)
  Lv.141-180 = lerp(300, 400, level, 141, 180)
  Lv.181-220 = lerp(430, 560, level, 181, 220)
  Lv.221-254 = lerp(600, 800, level, 221, 254)
```

插值函数：

```text
lerp(min, max, level, start, end)
= round(min + (max - min) * (level - start) / (end - start))
```

累计经验口径：

```text
total_required_exp(level)
= sum(required_exp(n) for n in 1..level-1)
```

由累计经验反推等级：

```text
level_from_exp(exp):
  level = 1
  while level < 255 and exp >= required_exp(level):
    exp -= required_exp(level)
    level += 1
  return { level, current_level_exp: exp, next_level_required: required_exp(level) }
```

这样可以保留现有 `experience` 字段作为累计成长值，不需要把数据库里的经验清零或重写成阶段内经验。

### 关键体验锚点

曲线调参要看体验锚点，而不是只看数学平滑。

| 用户类型 | 典型日行为 | 日成长值 | 预期体验 |
|---|---|---:|---|
| 轻度用户 | 打开 + 创建少量任务 | 10-20 | 前 10 级仍能稳定前进 |
| 标准用户 | 完成 1 次完整工作流 | 35-45 | Lv.1-60 有明显成长感 |
| 重度用户 | 多任务 + 多次总结/导出 | 80-140 | 中期推进更快但不会几天满级 |
| 长期用户 | 每周稳定使用 | 250-500/周 | Lv.181 后约周级推进 |

可接受目标：

- 标准用户第 1 周能进入 Lv.10-20。
- 标准用户第 1 个月能进入 Lv.40-70。
- 标准用户半年后仍有长期目标。
- 满级应是长期陪伴纪念，不是常规短周期目标。

### 满级处理

达到 Lv.255 后：

- `level` 固定为 `255`。
- `experience` 继续累计，作为历史陪伴总量。
- UI 不再显示“距离下一级”，改为“满级陪伴值”或“累计成长值”。
- 食物继续可使用，仍写入事件流水和累计经验。
- 工作行为继续产出 LP 和长期统计。

满级不能让用户感觉系统失效。等级停止，但陪伴记录、LP 经济、商品收集、纪念台词仍继续运转。

## 食物经验策略

食物提供固定成长值。

同一种食物在 Lv.1 和 Lv.200 时提供的成长值必须一致。后期食物占比变低，是因为升级所需成长值增加，而不是食物被削弱。

| 食物档位 | 价格区间 | 固定成长值 | 定位 |
|---|---:|---:|---|
| 日常小食 | 25-45 LP | +3 到 +6 | 前期常用，轻量照顾 |
| 轻量甜点 | 50-70 LP | +7 到 +10 | 日常补充 |
| 正餐/高级甜点 | 75-95 LP | +11 到 +16 | 中期主力 |
| 稀有食物 | 100-140 LP | +18 到 +24 | 阶段冲刺 |
| 纪念食物 | 160+ LP | +28 到 +36 | 后期稀有奖励 |

示例：

```text
Lv.8 升级需要 25 成长值，+12 食物很明显。
Lv.88 升级需要 160 成长值，+12 食物是有效补充。
Lv.220 升级需要 600 成长值，+12 食物主要是陪伴反馈。
```

这保证食物价值稳定，也避免用户觉得后期系统暗中削弱食物。

### 食物成长值表

当前代码中食物成长值由价格、羁绊阶梯和阶段门槛计算，范围偏保守。255 级方案建议改为显式表或显式字段，避免后续商品价格调整意外改变成长值。

推荐字段：

```text
growthValue: number
```

推荐初始映射：

| 商品 | 当前定位 | 建议成长值 |
|---|---|---:|
| 巧克力曲奇 / 纸杯蛋糕 / 粉色甜甜圈 | 日常小食 | +4 |
| 珍珠奶茶 / 冰淇淋甜筒 / 铃铛布丁 | 轻量甜点 | +6 |
| 糖果罐 / 焦糖布丁 / 三明治 | 日常补充 | +8 |
| 水果挞 / 紫色马卡龙 / 奶油蛋糕 | 中级甜点 | +10 |
| 元气便当 / 巧克力蛋糕 | 正餐/高级甜点 | +12 到 +16 |
| 草莓奶油蛋糕 | 高级陪伴甜点 | +18 |

后续新增纪念食物可以做到 `+24`、`+30`、`+36`，但应通过等级和价格控制稀缺性。

食物成长值必须在这些位置保持一致：

- 商店卡片。
- 商品详情窗口。
- 个人仓库卡片。
- 使用确认弹窗。
- 使用后的事件流水。
- 宠物中心最近事件。

如果任一位置显示值和实际入账值不同，用户会认为系统不可信。

## LP 经济策略

LP 是工作价值货币，不是真钱货币。

普通用户一天获得约 `45-60 LP`。据此反推购买节奏：

| 消费内容 | 价格建议 | 用户节奏 |
|---|---:|---|
| 普通食物 | 25-60 LP | 每天可以买 1 个 |
| 中级食物 | 70-100 LP | 1-2 天攒 1 个 |
| 高级食物 | 110-160 LP | 2-4 天攒 1 个 |
| 普通装扮 | 120-260 LP | 3-6 天攒 1 个 |
| 场景 | 180-480 LP | 1-2 周目标 |
| 高级装扮/场景 | 500+ LP | 长期目标 |

LP 不能过度膨胀。食物可以让用户每天有消费出口，装扮和场景承担长期攒点目标。

### LP 收支结构

LP 经济应保持“每天可小额消费，阶段性可攒大件”的节奏。

| 周期 | 推荐 LP 收入 | 推荐消费出口 |
|---|---:|---|
| 每日 | 45-60 | 1 个普通食物或低价道具 |
| 每周 | 250-400 | 1 个普通装扮或基础场景 |
| 每月 | 1000-1800 | 1-3 个高价值装扮/场景/纪念内容 |

不建议通过高额每日签到制造通胀。LP 应主要来自真实工作完成，而不是打开应用挂机。

### 价格带规则

商品价格应与解锁等级同步上升，但不能只按等级机械翻倍。

| 商品类型 | 低阶 | 中阶 | 高阶 | 终局 |
|---|---:|---:|---:|---:|
| 食物 | 25-60 | 70-120 | 130-180 | 200+ |
| 道具 | 35-90 | 100-180 | 200-320 | 360+ |
| 装扮 | 120-260 | 280-520 | 560-900 | 1000+ |
| 场景 | 180-480 | 520-900 | 960-1500 | 1800+ |
| 徽章 | 0 | 0 | 0 | 0 |

徽章原则上不售卖，主要通过里程碑自动获得。若未来出现可购买纪念章，也必须和成就徽章视觉区分。

## 每日节奏

不建议给食物成长值做递减。建议控制的是获取入口，而不是削弱已购买食物。

推荐限制：

- 互动类成长值每日上限：每类 20 次。
- 每日打开奖励按自然日去重。
- 工作流奖励按任务 ID 去重。
- 食物不限每日使用，但受 LP 获取速度和购买成本自然约束。
- 每日盲盒每天 10 次，按本地自然日重置，奖池完整展示，来自宠物商店但排除宠物本体。
- 每日盲盒可以产出装扮、场景、道具、食物、徽章和“什么都没抽中”；消耗品叠加，已拥有的非消耗品转为少量 LP 补偿。
- 每日盲盒是免费福利入口，不能购买额外次数，不能作为后期主要 LP 来源，避免破坏工作价值货币节奏。

如果未来需要控制极端刷食物，可以限制每日购买数量或部分食物库存刷新，而不是降低食物经验值。

## 反刷与幂等规则

成长系统需要防止重复发放，而不是惩罚正常用户。

### 工作事件幂等

必须以事件唯一键控制重复奖励：

```text
source_type = workflow_reward
source_key = event_type + event_source + stable_metadata
```

要求：

- 同一个任务的同一个工作事件只发放一次完整成长值和 LP。
- 失败后重试成功，只对最终成功事件发放。
- 后台恢复、应用重启、轮询重复回调不能重复发放。
- 事件流水可以记录重复触达，但奖励值必须为 0 或不入账。

### 互动限制

互动是情感入口，不是主线刷分入口。

建议：

- 每类互动每日最多奖励 20 次。
- 超过上限后仍可播放动作或台词，但不再发放成长值和 LP。
- UI 不需要强提醒“达到上限”，避免破坏陪伴感。
- 事件文案可以轻量表达“我先安静陪你，不用一直点我”。

### 食物限制

食物不做经验递减，但要通过 LP 和库存自然约束。

可选策略：

- 普通食物不限购买。
- 高级食物每日限购 1-3 个。
- 纪念食物每周或阶段限购。
- 活动食物必须有明确结束时间和本地可解释规则。

第一阶段不建议做复杂刷新商店。先保持简单、可理解、可测试。

## 商品解锁策略

商品解锁以等级为主，里程碑为辅。

| 内容 | 解锁条件建议 |
|---|---|
| 基础食物 | Lv.1 |
| 普通食物 | Lv.5 |
| 普通装扮 | Lv.10 |
| 基础场景 | Lv.20 |
| 中级食物 | Lv.30 |
| 高级装扮 | Lv.50 |
| 高级场景 | Lv.80 |
| 稀有食物 | Lv.100 |
| 纪念徽章 | Lv.140+ 或里程碑 |
| 顶级装扮/场景 | Lv.180+ |
| 终局纪念内容 | Lv.221+ |

`levelGate` 应成为主要字段。`stageGate` 可以保留用于展示和兼容，但不要成为核心判断。

### 等级解锁矩阵

推荐把商品内容分布到 8 个陪伴阶段，避免某几个等级突然集中解锁。

| 等级段 | 食物 | 道具 | 装扮 | 场景 | 徽章 |
|---|---|---|---|---|---|
| Lv.1-10 | 基础小食 | 基础互动道具 | 低阶配饰 | 无或极少 | 入门徽章 |
| Lv.11-30 | 日常甜点 | 专注/鼓励道具 | 日常配饰 | 基础桌面物件 | 任务数徽章 |
| Lv.31-60 | 正餐类 | 庆祝/恢复道具 | 主题配饰 | 阅读/休息场景 | 转写徽章 |
| Lv.61-100 | 高级甜点 | 深度陪伴道具 | 高级配饰 | 工作角落场景 | 总结徽章 |
| Lv.101-140 | 稀有食物 | 低频强反馈道具 | 稀有装扮 | 情绪场景 | 活跃徽章 |
| Lv.141-180 | 阶段食物 | 纪念道具 | 羁绊装扮 | 羁绊场景 | 长期徽章 |
| Lv.181-220 | 高阶稀有食物 | 长期道具 | 顶级装扮 | 顶级场景 | 高阶徽章 |
| Lv.221-255 | 纪念食物 | 满级纪念道具 | 终局装扮 | 终局场景 | 满级徽章 |

### 里程碑解锁矩阵

里程碑应围绕 Liberty 的真实工作价值。

| 里程碑 | 计数键 | 推荐解锁 |
|---|---|---|
| 创建任务 1/5/20/50 次 | `tasks_created` | 入门、稳定使用、长期使用徽章 |
| 完成转写 5/20/50 次 | `transcriptions_completed` | 转写主题徽章、专注场景 |
| 完成 AI 总结 5/20/50 次 | `summaries_completed` | 总结主题徽章、会议场景 |
| 导出结果 10/30/100 次 | `exports_completed` | 交付徽章、纪念场景 |
| 连续活跃 3/7/14/30 天 | `active_days` | 陪伴徽章、长期台词 |
| 深色主题使用 3/7/30 天 | `dark_theme_days` | 夜间场景、月光徽章 |

里程碑商品适合自动入库，不适合要求用户再花 LP 购买。

### 商品状态规则

商品状态优先级应稳定：

```text
coming_soon
→ equipped
→ owned
→ achievement
→ locked
→ insufficient
→ available
```

解释：

- 未开放商品永远优先显示 `coming_soon`。
- 已装备优先于已拥有。
- 成就类商品在未达成前显示成就条件，不显示“购买”。
- 条件未满足优先于 LP 不足。
- 条件满足但 LP 不足才显示 `insufficient`。

这能避免用户看到“LP 不足”却不知道其实等级也不够。

## 反馈体系

宠物反馈必须服务情感，不要像传统数值游戏。

| 事件 | 反馈 |
|---|---|
| 吃食物 | 治愈台词、吃东西动作、`+成长值` 浮动动画 |
| 升级 | 庆祝台词、短动画 |
| 阶段突破 | 更强台词、解锁提示 |
| 装扮 | 宠物回应“戴好了” |
| 场景 | 宠物回应“这里更像我们的角落” |
| 徽章 | 宠物回应“这是我们一起攒下来的证明” |
| 长期活跃 | 更深层陪伴台词 |

食物台词方向：

- 被照顾感：谢谢你记得我。
- 陪伴感：我会继续在这里陪你。
- 恢复精神：我感觉更有力气了。
- 少量数值：成长值悄悄 +N。

### 分阶段反馈语气

随着阶段提升，宠物台词不只是更热闹，而是更理解用户。

| 阶段 | 台词方向 | 示例语气 |
|---|---|---|
| 小小初遇 | 认识、好奇、轻快 | “我还在认识你的节奏。” |
| 轻轻熟悉 | 记住习惯、短句回应 | “这个时间你常常会开始工作。” |
| 稳定陪伴 | 鼓励完成、陪用户收尾 | “我们把这一段做完就休息一下。” |
| 一起成长 | 承认积累、共同推进 | “这些任务不是白做的，我都有记着。” |
| 默契养成 | 更少打扰、更贴节奏 | “你专注的时候，我就安静一点。” |
| 深深羁绊 | 长期陪伴、情绪支持 | “你忙了这么久，我还在。” |
| 长久相伴 | 回看历史、纪念感 | “这已经是我们一起完成的第很多次了。” |
| 不离不弃 | 沉淀、归属、满级纪念 | “我已经不只是刚来的那个小伙伴了。” |

### 反馈触发优先级

同一时刻多个事件发生时，反馈优先级建议：

```text
阶段突破
→ 升级
→ 里程碑解锁
→ 商品装备/使用
→ 工作完成
→ 普通互动
→ 主动陪伴台词
```

高优先级反馈可以覆盖低优先级反馈，但低优先级事件仍要写入流水。

### 反馈冷却

为避免打扰：

- 主动台词需要冷却时间。
- 用户处于专注模式时减少主动台词。
- 转写或总结进行中不要频繁弹出非关键反馈。
- 阶段突破和升级可以突破冷却，但要短。
- 食物和装备反馈由用户主动触发，不需要强冷却。

## UI 展示策略

宠物阶梯区域应展示：

```text
当前等级：Lv.88
当前阶段：一起成长
当前成长值：xxxxx
距离下一级：xx / xxx
下一阶段：默契养成 Lv.101
```

食物卡片展示：

```text
成长值 +12
价格 75 LP
持有 x3
```

个人仓库食物也必须展示固定成长值，避免用户不知道食用收益。

### 商品详情窗口

商品详情窗口用于解释“这是什么、为什么锁住、拥有后有什么意义”。

应展示：

```text
商品图
商品名称
分类
羁绊阶梯/稀有度
状态
价格
持有数量
等级要求
阶段要求
里程碑要求
成长值（食物）
来源（已拥有商品）
```

交互要求：

- 商店卡片双击打开系统级详情窗口。
- 仓库卡片双击打开同一个详情窗口。
- 详情窗口不承担购买/装备主操作，第一阶段只做解释和预览。
- 图片区域可以使用 3D 翻转表达商品背面信息。
- 详情窗口必须有 Tauri capability，能读取商店状态。

详情窗口的价值是降低用户对锁定条件、成长值、来源和商品意义的疑问。

### 宠物中心成长展示

255 级落地后，宠物中心不能继续展示 `stageProgress / 20`。

应改为：

```text
当前等级：Lv.N
当前阶段：阶段名
本级成长：current_level_exp / next_level_required
累计成长：experience
下一阶段：阶段名 Lv.X
```

满级时改为：

```text
当前等级：Lv.255
当前阶段：不离不弃
累计成长：experience
陪伴天数：active_days
累计完成：任务 / 转写 / 总结 / 导出
```

## 长期目标

到 Lv.255 后不建议让系统停止。

满级后可以进入纪念循环：

- 继续获得 LP。
- 继续购买食物、装扮、场景。
- 解锁满级纪念台词。
- 记录陪伴天数、完成任务数、总结次数等长期数据。

满级不是结束，而是“这个宠物已经成为长期伙伴”的标记。

## 数据模型与迁移策略

### 保留字段

现有字段可以继续使用：

```text
pet_profile.experience
pet_profile.level
pet_profile.stage
pet_wallets
pet_inventory
pet_event_ledger
pet_economy_ledger
pet_milestone_counters
```

其中 `experience` 应解释为累计成长值，而不是当前等级内成长值。

### 新增或调整字段

建议为商品目录增加显式成长值字段：

```text
growth_value INTEGER DEFAULT 0
```

如果第一阶段仍将目录写在 Rust seed 中，也要让 seed 显式携带 `growth_value`，不要继续由价格推导。

建议增加曲线工具函数：

```text
required_exp_for_level(level)
level_snapshot_from_experience(experience)
stage_from_level(level)
next_stage_from_level(level)
```

前端不应自行计算等级曲线。Rust 返回的 store/profile snapshot 应包含足够展示字段，避免前端和后端曲线不一致。

### 迁移原则

从线性等级迁移到 255 级曲线时：

- 不清空用户现有经验。
- 不降低累计经验。
- 允许用户等级因新曲线重新映射后发生变化，但要避免明显“降级感”。
- 如果新曲线导致老用户等级下降，应考虑一次性迁移补偿或保底等级。
- 旧的 `baby/growing/mature` 阶段需要映射到 8 阶段。

推荐保底：

```text
new_level = max(level_from_exp(experience), legacy_level_floor)
```

`legacy_level_floor` 可以只用于首次迁移，避免老用户打开应用后突然降级。

### 阶段枚举

当前阶段枚举是：

```text
baby
growing
mature
```

255 级方案建议扩展为稳定内部枚举：

```text
first_meet
familiar
steady_companion
grow_together
tacit_bond
deep_bond
long_company
bond_forever
```

中文展示名可以继续使用“小小初遇、轻轻熟悉、稳定陪伴、一起成长、默契养成、深深羁绊、长久相伴、不离不弃”。

## 工程执行细节

本节基于当前 Liberty 项目结构确认，目的是把策略转成可直接执行的工程任务。

### 当前代码现状

宠物成长核心需要由后端统一收敛，主要涉及：

```text

apps/desktop/src-tauri/src/infrastructure/repositories/pet_store.rs
```

落地前这些路径中存在过旧线性等级算法：

```text

```

前端宠物中心曾自行计算阶段进度：

```text

```

因此 255 级落地不能只改 UI，也不能只改其中一个 Rust 文件。等级曲线必须以后端为唯一来源，再由前端消费后端快照。

### 必须新增的后端模块


职责：

- 提供 LP 阶段系数。

### 推荐实施拆分

为了降低风险，建议按以下 PR/任务拆分：

1. 曲线内核：新增 255 级曲线函数、阶段映射、单元测试。
2. 数据迁移：把现有累计经验映射到新等级，保留旧用户体验。
3. UI 展示：宠物中心改为本级成长/下阶段展示。
4. 食物字段：商品目录改为显式 `growthValue`，同步商店、仓库、详情、事件。
5. 商品门槛：重排 `levelGate`，把内容分布到 8 个阶段。
6. 反馈池：补升级、阶段突破、食物、装备、满级台词。
7. 观测与调参：记录等级分布、LP 收支、商品购买和食物使用。

每一步都应该能单独验收，不能一次性把曲线、商品、UI、台词全部混在一起改。

### 1. 曲线内核验收

## 策略结论

Liberty 宠物体系应采用：

```text
255 级长期成长
+ 分段升级曲线
+ 工作行为主线成长
+ LP 经济
+ 固定食物成长值
+ 等级解锁内容
+ 情感化桌宠反馈
```

这套系统的关键不是让用户快速刷满，而是让每一次真实工作都能积累成长期陪伴关系。
